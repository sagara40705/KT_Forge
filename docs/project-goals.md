# KT_Forge の目標

更新: 2026-10-10 JST。

## 選んだ目標

2026-10-12の見下ろしの3Dアクション、原神のようなアニメ調の雰囲気。
骨格アニメーションが必要で、多数の敵・エフェクトを想定する。提出期限は未確定。
RenderGraphを維持し、Forwardから始める。敵の数と同時ライト数を分けて計測する。

制作に必要な描画の順番は、骨格/GPU Skinning → 主光源と基本トゥーン/影 → 半透明・加算/Particle → HUD → 見た目の調整。
最初の遊べる場面は一キャラクターの移動・攻撃、一種類の敵、背景、当たり判定を組み合わせる。
これを待たずに多数の描画方式を一括導入しない。Deferred/Forward+はライト負荷が実測上の課題になった時に再判断する。

Windows x64 / DirectX 12 / C++20専用の基盤で、小さな3Dゲームを完成させます。他OS・Vulkan・複数backendへの抽象化は作りません。

ゲームの完成とともに、描画の一フレーム、CPU/GPUの役割、所有・失敗条件・設計理由を本人が説明できることを成果とします。

KT_Engine2に似た最終構造は許容しますが、過去の完成実装・モジュール数・Ballゲームを自動継承しません。責務と所有を直接追える規模を優先します。

## 完成条件の案

まず小さな3D空間で入力により状態が変わり、達成/失敗、結果、再開、終了まで一回分を遊べるMVPを作ります。PBR、Deferred、cascade shadow、Editor、SDKの完成をMVPの条件にしません。

その後、選んだ内容を磨き、対象PCの条件、既知の制約、起動・操作方法、依存物・権利表記を整えます。ゲームのジャンル、タイトル、MVPの具体的な遊び、期限、性能目標は未決定です。

## 拡張と公開

非描画領域ではJolt/Assimp等の利用を認める方針ですが、個別採用・版・管理方法は必要性を見て判断します。WindowはGLFW継続です。数学やGPU寿命の詳細を含む技術契約はarchitectureに集約します。
